# Квартирукупить

Сайт новостроек и квартир Калининграда с каталогом, картой объектов и собственной административной панелью.

## Возможности

- Каталоги новостроек и элитных квартир: поиск, фильтры, сортировка, карточки и карта.
- Страницы объектов с галереей, характеристиками, ипотечным калькулятором и формой обращения. Кнопка карты открывает каталог с выбранным объектом.
- Связи между ЖК и квартирами, ручное редактирование и публикация объектов.
- Импорт из CRM RF39 и НМаркет с сохранением выгрузок и созданием черновиков.
- Обрезка, настройка цветового тона и локальное улучшение фотографий через Real-ESRGAN.
- Блог, обработка заявок, метаданные страниц, sitemap и robots.txt.

**Стек:** Nuxt 3, Vue 3, TypeScript, Tailwind CSS, Prisma, PostgreSQL 17, Leaflet и Docker Compose. Тесты — Node.js Test Runner и Playwright.

## Быстрый запуск

Нужны Git и Docker с Compose v2. На Windows используйте Docker Desktop в режиме Linux-контейнеров. Для клонирования нужен доступ к приватному репозиторию.

```bash
git clone https://github.com/CYCOSER/kvartirukupit.git
cd kvartirukupit
cp .env.example .env
```

В PowerShell можно использовать `Copy-Item .env.example .env`. Копируйте шаблон только при первом запуске: существующий `.env` нужно сохранить.

Заполните обязательные настройки в `.env`:

| Переменная | Значение |
| --- | --- |
| `POSTGRES_PASSWORD` | Длинный случайный пароль БД. Для готового Compose используйте буквы и цифры: пароль подставляется в URL подключения. |
| `ADMIN_EMAIL` | Email для входа в админку. |
| `ADMIN_PASSWORD` | Уникальный пароль длиной от 16 символов. Заглушка из шаблона не принимается. |

На Linux подготовьте каталог выгрузок НМаркет для пользователя контейнера с UID 1000:

```bash
mkdir -p .data/nmarket
sudo chown 1000:1000 .data/nmarket
```

Запустите сервисы:

```bash
docker compose up -d --build
docker compose ps
```

Первая сборка скачивает зависимости и веса модели улучшения фото и может занять несколько минут. Сервису улучшения выделены 2 CPU и до 4 ГБ RAM; веб-приложению и БД также нужны ресурсы.

- **Сайт:** http://localhost:3100
- **Админка:** http://localhost:3100/admin-console-9Xk6uiIs/login
- **Проверка доступности:** http://localhost:3100/api/health

При старте веб-контейнер применяет миграции и выполняет начальное наполнение: создаёт администратора, статьи и каталог из `data/curated/`. В репозитории есть три начальных ЖК с локальными изображениями. Доступ к RF39 и НМаркет для первого запуска не нужен.

Повторный запуск не сбрасывает существующего администратора и не восстанавливает удалённые начальные статьи. **Изменение `ADMIN_PASSWORD` в `.env` не меняет пароль уже созданной учётной записи.**

## Страницы

| Адрес | Назначение |
| --- | --- |
| `/` | Главная, подборка объектов и форма обращения. |
| `/catalog` | Новостройки: ЖК и квартиры, список и карта. |
| `/elite` | Элитные квартиры, список и карта. |
| `/catalog/[slug]` | Страница ЖК или квартиры. |
| `/blog`, `/blog/[slug]` | Блог и статьи. |
| `/privacy` | Политика обработки персональных данных. |

В форме обращения обязательны телефон и согласие на обработку данных; имя и комментарий можно оставить пустыми. Заявка со страницы объекта сохраняет связь с ним.

## Настройки

Полный шаблон — [`.env.example`](.env.example). Реальные пароли и ключи хранятся в локальном `.env`, который исключён из Git.

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт сайта на хосте; по умолчанию `3100`. |
| `NUXT_PUBLIC_SITE_URL` | Полный адрес сайта, по умолчанию `http://localhost:3100`. Используется для ссылок, SEO и проверки источника запросов. |
| `NUXT_PUBLIC_PHONE` | Контактный телефон на сайте. |
| `NUXT_PUBLIC_LEGAL_NAME`, `NUXT_PUBLIC_LEGAL_ADDRESS`, `NUXT_PUBLIC_LEGAL_EMAIL`, `NUXT_PUBLIC_INN` | Реквизиты владельца сайта для контактных и юридических блоков. |
| `NUXT_RF39_TOKEN` | Серверный ключ для импорта из CRM RF39. |
| `NUXT_NMARKET_FEED_URL` | Приватная HTTPS-ссылка XML-выгрузки на `ecatalog-service.nmarket.pro`. |
| `NUXT_MAP_SEARCH_URL` | Совместимый с Nominatim сервис поиска адресов; по умолчанию `https://nominatim.openstreetmap.org/search`. |

При смене порта или домена обновите `NUXT_PUBLIC_SITE_URL`: его origin должен совпадать с адресом, открытым в браузере. После изменения переменных пересоздайте веб-контейнер:

```bash
docker compose up -d --no-deps --force-recreate web
```

Для публикации настройте домен, HTTPS, обратный прокси и реквизиты владельца сайта. Compose публикует веб-порт только на `127.0.0.1`; PostgreSQL и сервис улучшения фото наружу не открываются. В production с HTTPS защищённый режим cookie сессии включается автоматически.

## Каталог и импорты

В админке можно создать ЖК или квартиру, загрузить изображения, задать адрес и положение на карте, связать квартиру с ЖК и опубликовать карточку. Отметка элитного объекта доступна только квартирам. На странице ЖК показываются его опубликованные квартиры; удаление ЖК сохраняет квартиры, снимая привязку.

### RF39 и НМаркет

Подключите источник в `.env`, затем откройте раздел импорта в админке.

| Источник | Работа с выгрузкой |
| --- | --- |
| **CRM RF39** | При первом открытии загружается полный снимок. Далее используется сохранённая версия; кнопка «Обновить из CRM» скачивает новую. При импорте из этого раздела доступность выбранного объекта повторно проверяется в CRM. |
| **НМаркет** | При открытии используется сохранённый XML. Если его ещё нет, нажмите «Обновить из Нмаркета». Обновление скачивает полный файл и заменяет сохранённую версию. |

Новая выгрузка заменяет старую только после успешного полного скачивания и проверки. Ошибка загрузки или записи оставляет предыдущий файл. Для обоих источников действуют пределы 128 МБ и 20 000 записей.

Импорт поддерживает ЖК и квартиры и создаёт **черновики**. Перед публикацией проверьте цену, наличие, адрес, характеристики и фотографии. Повторный импорт того же ID источника сохраняет существующую карточку и ручные правки; постоянной автоматической синхронизации нет.

Кнопка «Найти и привязать квартиры» в редакторе ЖК ищет совпадения в базе сайта и подключённых источниках. Выбор свежей или сохранённой выгрузки общий для CRM RF39 и НМаркет и применяется к поиску и импорту выбранных квартир. В сохранённом режиме используются последние успешно сохранённые данные каждого источника; если файла нет, нужно сначала обновить выгрузку. Неоднозначные совпадения пропускаются. Карточки одного объекта из разных источников могут потребовать ручного разбора дубликатов.

### Начальные данные из репозитория

JSON находятся в [`data/curated/`](data/curated), изображения — в [`public/images/projects/`](public/images/projects). Импортёр проверяет структуру данных и наличие файлов до записи в БД.

```bash
# Применить данные, уже находящиеся в работающем контейнере
docker compose exec web npm run db:import

# Локально: импортировать свой каталог JSON
npm run db:import -- path/to/curated
```

При изменении файлов в репозитории пересоберите образ. Снимки с прежней или более старой датой не перезаписывают карточки. Более новый снимок обновляет данные, сохраняя настройки публикации, статус, slug и ручные изображения. Формат и проверки — в [`shared/import-catalog.ts`](shared/import-catalog.ts) и [`scripts/import-catalog.ts`](scripts/import-catalog.ts).

## Фотографии и карты

Редактор фотографий поддерживает обрезку и сдвиг цветового тона. Загруженные и импортированные изображения сохраняются в WebP без потерь; планировки показываются целиком. Обычное редактирование работает от сохранённой основы, не накапливая повторные обрезки.

Улучшение фото выполняет отдельный локальный CPU-сервис Real-ESRGAN. Первые фотографии объектов с недостаточным разрешением ставятся в фоновую очередь; остальные можно улучшить вручную. Изображения не отправляются во внешний сервис обработки.

Ширина, высота и цвет доступны и для улучшенного фото. После сохранения его правок улучшенный файл становится основой дальнейшего редактирования и сброса; исходный файл не удаляется. Пределы и устройство сервиса — в [`services/upscale/README.md`](services/upscale/README.md).

Карта использует Leaflet и тайлы OpenStreetMap, поиск адресов — Nominatim. Для тайлов и поиска нужен доступ к соответствующим сервисам. Кеш и ограничение частоты запросов поиска рассчитаны на один веб-процесс; несколько реплик требуют общего кеша и лимитера.

## Данные и резервные копии

Имя Compose-проекта — `newh`, независимо от имени папки репозитория. При стандартном запуске используются:

| Хранилище | Содержимое |
| --- | --- |
| Том `newh_postgres_data` | PostgreSQL: объекты, статьи, заявки, пользователи и очередь обработки фото. Таблицы приложения находятся в схеме `app`. |
| Том `newh_uploads` | Загруженные фотографии, обложки и результаты обработки. |
| Том `newh_rf39_snapshots` | Последняя сохранённая выгрузка RF39. |
| Каталог `.data/nmarket/` на хосте | Последняя сохранённая XML-выгрузка НМаркет. |

Для полной резервной копии сохраняйте БД, изображения, обе выгрузки и `.env`. Git содержит код и начальную подборку, **но не текущее содержимое сайта**. На время согласованного копирования БД и файлов приостановите изменения в админке.

Пример копии БД вне репозитория, без перенаправления бинарного потока через PowerShell:

```bash
docker compose exec -T db pg_dump -U newh -d newh -Fc -f /tmp/kvartirukupit.dump
docker compose cp db:/tmp/kvartirukupit.dump ../kvartirukupit.dump
```

Это только копия БД; изображения и выгрузки архивируются отдельно. Выбирайте отдельное имя файла для каждой резервной копии.

Обычная пересборка сохраняет данные. **`docker compose down -v` удаляет именованные тома**, включая БД и загруженные изображения.

## Обновление и обслуживание

```bash
git pull --ff-only
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 web
```

Логи БД и обработки фото доступны через `docker compose logs db` и `docker compose logs upscale`. Команды `docker compose stop` и `docker compose up -d` останавливают и запускают сервисы с сохранением данных.

## Локальная разработка

Нужны Node.js 22+ и доступный PostgreSQL. Для разработки без Docker добавьте в `.env` `DATABASE_URL` со схемой `app`, например:

```dotenv
DATABASE_URL=postgresql://newh:password@localhost:5432/newh?schema=app
UPLOAD_DIR=.data/uploads
```

Используйте собственные реквизиты БД. База из стандартного Compose не публикует порт на хост: для локального Nuxt нужен отдельно настроенный доступный PostgreSQL.

```bash
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev -- --port 3100
```

В этом режиме снимки по умолчанию находятся в `.data/rf39/snapshot.json` и `.data/nmarket/snapshot.xml`; пути меняются через `NUXT_RF39_SNAPSHOT_PATH` и `NUXT_NMARKET_SNAPSHOT_PATH`. В Compose пути настроены на постоянные хранилища. Автоматическое улучшение фото вне Compose по умолчанию отключено.

### Проверки

```bash
npm run typecheck
npm test
npm run build

npx playwright install chromium
npm run test:e2e
```

E2E не запускает сайт автоматически: нужен работающий экземпляр с наполненным каталогом и администратором из `.env`. Используйте тестовую БД — часть сценариев создаёт и удаляет временные объекты. Адрес задаётся через `PLAYWRIGHT_BASE_URL`, по умолчанию `http://localhost:3100`. Для установленного Edge можно задать `PLAYWRIGHT_CHANNEL=msedge` вместо установки Chromium.

## Структура проекта

```text
pages/             Публичные страницы и админка
components/        Каталог, карта, формы и редакторы
composables/       Общая логика Vue
assets/, public/   Стили, шрифты и статические изображения
server/            API, авторизация, импорт и обработка данных
shared/            Типы, схемы валидации и общие функции
prisma/            Схема БД, миграции и начальное наполнение
data/curated/      Начальные карточки ЖК
scripts/           Запуск контейнера и импорт локального каталога
services/upscale/  Локальный сервис улучшения фотографий
tests/             Модульные и браузерные проверки
```

Локальные пароли, выгрузки, загрузки, кэши, результаты тестов и сборки исключены из Git. Конфигурация запуска находится в [`compose.yaml`](compose.yaml), команды npm — в [`package.json`](package.json).
