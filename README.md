# Квартирукупить

Сайт новостроек Калининграда на Vue 3 / Nuxt 3, PostgreSQL и Docker. Структура, меню, раздвигающиеся панели и админка перенесены из проекта «Дом купить», оформление выполнено в синих тонах.

Каталог хранится в PostgreSQL; начальная подборка загружается из локальных JSON-файлов. В ней представлены ЖК «Адрес счастья», «Ратсхоф Дом» и «Тихий дом» из выгрузки НМаркет.ПРО. Начальная цена каждого ЖК — минимум по всем предложениям квартир в продаже в полной локальной выгрузке, фотографии и планировки представлены выборочно. Сведения об источниках сохраняются для редактора и не выводятся в публичных описаниях. Импорт новых карточек из RF39 и НМаркет запускается вручную в админке.

## Страницы

- `/` — главная, подборка ЖК, порядок покупки и обращение.
- `/catalog` — каталог с фильтрами и боковой панелью.
- `/catalog/[slug]` — сведения о ЖК, галерея, ипотечный калькулятор и заявка.
- `/blog` и `/blog/[slug]` — статьи с SEO-полями и перелинковкой.
- `/privacy` — политика обработки персональных данных.
- `/morskoy-kabinet-7q4x/login` — админка: ЖК и квартиры, предпросмотр карточек, изображения, публикация, заявки и редактор статей.

Страница продажи своего дома отсутствует. Для публикации заполните контактные и юридические реквизиты в `.env`.

## Запуск

Требуются Docker Desktop и Docker Compose.

```powershell
cd C:\Users\CYCOSER\Documents\rsite\newh
# Только при первом запуске, если .env отсутствует:
Copy-Item .env.example .env
# Задайте собственные POSTGRES_PASSWORD, ADMIN_EMAIL и ADMIN_PASSWORD.
docker compose up -d --build
```

Используйте уникальный пароль администратора длиной не менее 16 символов. Пароль PostgreSQL в URL должен состоять из букв и цифр либо быть корректно закодирован. Существующий `.env` сохраняйте при обновлении проекта.

Сайт: [localhost:3100](http://localhost:3100). Админка: [вход](http://localhost:3100/morskoy-kabinet-7q4x/login). При смене `PORT` также измените `NUXT_PUBLIC_SITE_URL`. Порт PostgreSQL на хост не публикуется.

При старте применяются миграции и локальный каталог. Администратор и пять начальных статей создаются при первоначальной настройке. Последующие перезапуски сохраняют редакторские изменения, удаление и переименование статей.

```powershell
docker compose ps
docker compose logs --tail=50 web
docker compose stop
docker compose up -d
```

## Контент каталога

### Импорт из CRM RF39

В админке откройте «ЖК и квартиры → Импорт из CRM»: список открывается автоматически.
При первом открытии сервер получает все страницы CRM и сохраняет полный снимок.
Повторные открытия и переходы между страницами читают этот снимок без запросов в CRM;
дата выгрузки показывается над списком. Кнопка «Обновить из CRM» явно загружает новый
полный снимок. Выберите отдельные объекты или категорию и создайте черновики.
Импорт переносит название,
описание, адрес, координаты, цену, доступные характеристики и собственные фотографии
объекта. Корпус с вложенными планировками создаётся как ЖК; его квартиры можно затем
загрузить кнопкой поиска квартир в редакторе ЖК. Дома, участки, комнаты, коммерция и аренда
пока не соответствуют модели каталога и недоступны для выбора.

Для подключения задайте `NUXT_RF39_TOKEN` в `.env` и пересоздайте контейнер web.
Ключ используется только сервером в теле POST-запроса к `https://crm.rf39.ru/api/objects`.
Контакты собственников, агентов и приватные поля CRM на сайт не переносятся.
Снимок хранит только проверенные поля объектов и хеш привязки к API-ключу, без самого
ключа. Docker сохраняет файл в отдельном томе `rf39_snapshots`; для запуска без Docker
путь задаётся через `NUXT_RF39_SNAPSHOT_PATH` (по умолчанию `.data/rf39/snapshot.json`).
Кеш переживает перезапуск контейнера. Смена ключа требует нового полного снимка:
данные прежнего ключа не показываются. При ошибке обновления последний полный файл
сохраняется; частичная выгрузка его не заменяет. Повреждённый файл можно заменить
кнопкой обновления. Ограничения снимка: 20 000 объектов и 128 МБ.
В список попадают опубликованные неархивные объекты CRM. Созданные карточки сайта
всегда скрыты до ручной публикации; наличие и значения характеристик нужно проверить.
Перед импортом выбранный объект заново проверяется в CRM, поэтому устаревший снимок
не позволяет перенести уже снятое с публикации или архивное объявление.
Повторный импорт открывает существующую карточку по ID источника и не перезаписывает
ручные правки. Автоматической синхронизации нет. При ошибке скачивания фотографии
новая карточка не создаётся; импорт можно повторить. Фотографии хранятся в томе uploads.

### Импорт из НМаркет

На том же экране импорта выберите «НМаркет»: сохранённый список откроется автоматически. Задайте поиск и
фильтры по категории, городу, цене, площади и комнатам, затем создайте черновики
для выбранных объектов или всего результата фильтра. Источник подключается через
`NUXT_NMARKET_FEED_URL` в `.env`; после изменения пересоздайте контейнер web. Это
закрытая ссылка XML-выгрузки на `https://ecatalog-service.nmarket.pro`, она остаётся
на сервере и не попадает в публичные карточки или сообщения об ошибках.

Список содержит отдельные квартиры и ЖК, сгруппированные по ID НМаркет. Минимальная
цена ЖК считается по всем его предложениям продажи; если у любого предложения нет
корректной цены в рублях, цена ЖК остаётся неизвестной. Площадь и количество комнат
ЖК не заимствуются у отдельной квартиры. Фотографии ЖК не включают планы квартир;
при импорте квартиры её планы переносятся вместе с фотографиями. Контакты агентов
из XML не копируются. Неоднозначные адреса и сроки корпусов требуют ручной проверки.

Выгрузка читается потоково, ограничена 128 МБ и 20 000 предложений; снимок кешируется
в памяти одного web-процесса на 10 минут, чтобы страницы списка и выбранные импорты
не скачивали XML заново. Кнопка обновления обходит этот кеш. После полной загрузки и
проверки XML новый файл атомарно заменяет сохранённую выгрузку. При ошибке загрузки,
проверки или записи прежний файл сохраняется, а запрос сообщает об ошибке.
Для карточки загружаются до 100 изображений с `img.nmarket.pro`, до 10 МБ каждое.
Импорт создаёт только черновики, сохраняет ручные правки при повторе и не выполняет
автосинхронизацию. Прежние карточки из `data/curated` имеют отдельные идентификаторы:
они не объединяются с НМаркет по одному совпадению названия, поэтому перед импортом
ЖК проверьте наличие уже подготовленной вручную карточки.

При открытии раздела НМаркет автоматически загружается последняя сохранённая
выгрузка с её датой. Кнопка «Обновить из Нмаркета» запрашивает актуальные данные;
старый XML никогда не подставляется вместо неудачного живого запроса.
Файл `.data/nmarket/snapshot.xml` создаётся при первой успешной загрузке; ранее
сохранённый полный XML можно положить туда заранее. Docker подключает директорию
`.data/nmarket` для чтения и записи. На Linux предоставьте пользователю контейнера
`node` (UID 1000) право записи в эту директорию. Пока файла нет, сохранённый режим
сообщает, что выгрузка не настроена; кнопка обновления загрузит её. Для запуска без
Docker путь по умолчанию такой же; его можно изменить через `NUXT_NMARKET_SNAPSHOT_PATH`.

Дата сохранённой выгрузки берётся из `generation-date` XML, а при его отсутствии —
из времени изменения файла. Она показывается в списке и сохраняется в `sourceFetchedAt`
и предупреждении карточки. После замены файла кеш обновляется по его размеру и времени
изменения. XML читается локально; фотографии скачиваются с НМаркет при создании
черновика. Цена и наличие в сохранённом снимке могут устареть — проверьте их перед
публикацией. `snapshot=saved` в запросе списка и поле `snapshot: "saved"` при импорте
выбирают этот режим; клиент не может передать произвольный путь к файлу.

### Квартиры в ЖК и редактор фотографий

В редакторе квартиры выберите «Жилой комплекс квартиры». В сохранённой карточке ЖК
кнопка «Найти и привязать квартиры» одновременно проверяет базу сайта, НМаркет и CRM.
Новые квартиры создаются черновиками; существующие привязываются без перезаписи
ручных правок. Квартиры, уже связанные с другим ЖК, автоматически не перемещаются.
Каждый источник показывает свой результат; отдельную ошибку можно повторить,
а кнопку «Остановить» — использовать для прекращения следующих импортов.
Сохранённая выгрузка НМаркета выбирается явно и показывает дату данных.

Поиск использует ID источников либо уникальное точное название ЖК и город.
У корпуса дополнительно проверяется ID корпуса или точный адрес с номером дома.
Неоднозначные совпадения пропускаются. В дополнительных полях ЖК можно указать
`nmarketComplexId`, `rf39ComplexId` (RF39 `development.id`, весь ЖК) и
`rf39BuildingId` (RF39 `complex.id`, отдельный корпус). Сначала сохраните изменения.
Вложенная квартира CRM получает `sourceId=rf39-layout:<objectId>:<layoutId>`.
Повторный запуск не создаёт дубликат того же ID источника; одну квартиру из разных
систем нельзя надёжно объединить без общего идентификатора, поэтому их карточки
нужно проверить перед публикацией. Удаление ЖК сохраняет его квартиры без привязки;
публичная карточка показывает только опубликованные связи.

Планы НМаркета определяются по явной XML-метке, планы CRM — консервативно по изображению.
При импорте применяется единый сдвиг цветового тона RGB к синему: насыщенность и
светлота HSL, чёрный текст, серые линии и прозрачность сохраняются. Планировки
сохраняются в исходном разрешении в WebP без потерь и отображаются целиком без обрезки.
Сомнительные изображения остаются фотографиями. Все новые фото из НМаркета, CRM и
ручной загрузки также сохраняются в исходном разрешении в WebP без потерь.
В галерее кнопка «Редактировать фото» открывает обрезку и ползунок «Цветовой тон (RGB)».
Область задаётся выделением или координатами в пикселях оригинала. Каждое сохранение
применяет правки к сохранённому оригиналу; сброс обрезки и цвета возвращает его.
Для импортированных планов сохраняется и версия до автоматического изменения цвета.
Предпросмотр уменьшен только на экране: результат сохраняется в полном разрешении
выбранной области. WebP без потерь может занимать больше места. Лимит входного файла
остаётся 10 МБ и 40 мегапикселей; повторное редактирование не ограничено 10 МБ.
У старых загрузок уже потерянные детали не восстанавливаются: их нужно загрузить
заново из оригинального источника. Повторный импорт существующей карточки сохраняет
её ручные изменения и не заменяет старые фотографии.

В режиме карты адреса ищутся отдельно от объявлений через Nominatim. Поиск запускается по кнопке; повторные запросы кешируются, обращения к сервису ограничены одним в секунду. `NUXT_MAP_SEARCH_URL` позволяет заменить совместимый сервис поиска без пересборки образа. Текущий лимитер рассчитан на один web-процесс; перед запуском нескольких реплик нужны общий кеш и лимитер. На карте сохраняется обязательное указание авторства OpenStreetMap.

Для каждого ЖК используется файл `data/curated/<slug>.json`. Дополнительные записи об источниках можно хранить рядом в `<slug>.sources.md`; импортёр читает только JSON.

Текущие адреса:

- `/catalog/zhk-adres-schastya`
- `/catalog/zhk-ratskhof-dom`
- `/catalog/zhk-tikhiy-dom`

Формат JSON соответствует полям карточки в `shared/property.ts` и проверяется в `scripts/import-catalog.ts`. Идентификатор источника: `curated:<slug>`, режим: `curated`. `sourceFetchedAt` — дата проверки сведений в ISO-формате. Неизвестные цены и числовые характеристики остаются `null`.

Изображения находятся в `public/images/projects/<slug>/`. Для каждого изображения JSON хранит локальный `file`, содержательный `alt`, исходный HTTPS-адрес, ширину, высоту и `kind`. Рендер обозначается в подписи как рендер. В PostgreSQL сохраняются путь, подпись и порядок; остальные сведения остаются в исходном JSON.

`priceKind: "from"` означает минимальную цену квартиры в продаже по полному набору предложений ЖК. Цена сопровождается внутренним `priceSourceUrl`; отсутствие подтверждённой цены обозначается `null`. Импорт комплекса с ценой отдельного примера (`"example"`) отклоняется.

Экспортёр `../balthub/feeds/export_nmarket_to_newh.py` считает минимум из полного `nmarket-kaliningrad.xml`, независимо от количества квартир с загруженными планировками. Все записи этого файла — действующие предложения продажи на дату выгрузки; отдельного статуса бронирования источник не передаёт. Описание и подписи изображений не дополняются названием сервиса или примерами цен. При следующем экспорте сначала обновите полный файл выгрузки. Миграция `202610200001_catalog_available_prices` исправляет прежние цены и тексты только там, где они точно совпадают с первоначально импортированными значениями, сохраняя ручные правки и реальную дату получения источника.

После изменения локальных файлов пересоберите контейнер: данные и изображения включаются в образ. Чтобы применить каталог, уже находящийся внутри работающего контейнера:

```powershell
docker compose exec web npm run db:import
```

Вне Docker команда принимает каталог с JSON:

```powershell
npm run db:import -- path/to/curated
```

Импорт не обращается к сети. Он проверяет структуру данных и наличие локальных изображений до транзакции. Снимки с той же или более старой датой не перезаписывают карточку. Более новая дата применяет редакцию локального файла, сохраняя настройки публикации, выделения, статус, адрес страницы и ручные изображения из админки.

Шесть прежних карточек ДОМ.РФ при переходе однократно скрываются и получают режим `archived-domrf`. Они остаются в БД вместе с привязанными заявками. Их архивный снимок больше не используется для наполнения сайта.

## Данные и резервные копии

Используется прежняя база `newh`; таблицы приложения находятся в схеме `app`. Старые `public.projects` и `public.leads` сохраняются. Старые заявки импортируются повторяемо по идентификатору, без создания дубликатов и перезаписи их обработки.

Постоянные тома:

| Том | Содержимое |
| --- | --- |
| `newh_postgres_data` | PostgreSQL, схемы `app` и `public` |
| `newh_uploads` | Фотографии и обложки, загруженные через админку |

Прежний том `newh_project_images` больше не подключается; существующие данные в нём не удаляются. Резервная копия текущего сайта должна включать PostgreSQL, `newh_uploads` и исходные файлы контента. Команда `docker compose down -v` удаляет подключённые тома; обычная пересборка их сохраняет.

## Разработка и проверки

Требуются Node.js 22+ и PostgreSQL. Для локального запуска задайте `DATABASE_URL` со схемой `app`; Docker-база по умолчанию не доступна с хоста.

```powershell
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev -- --port 3100

npm run typecheck
npm test
npm run build
npm run test:e2e
```

Unit-тесты проверяют валидацию локального каталога, сохранение ручных изменений, однократное архивирование и поведение seed. E2E требует работающий сайт и администратора из `.env`.

Временные диагностические материалы находятся в `.tmp/` и исключены из Git и Docker-контекста.

### Улучшение фотографий

Compose запускает отдельный CPU-сервис Real-ESRGAN (2 ядра, до 4 ГБ RAM) в закрытой сети. Его порт не опубликован, фото не отправляются во внешние сервисы. Первая сборка скачивает PyTorch и проверенные веса модели; при работе интернет не нужен.

Раз в 30 секунд приложение проверяет первое фото каждого объекта, пропуская планировки. Если длинная сторона меньше 1920 px или короткая меньше 1080 px, фото попадает в постоянную очередь PostgreSQL. Так обрабатываются существующие объекты, импорт, новые загрузки и изменения порядка галереи. Обработка идёт по одному снимку, сайт продолжает работать. После сбоя сервера незавершённая задача возвращается в очередь по истечении 15-минутной аренды; ошибки автоматически повторяются до трёх попыток. Оригинал, обрезка и цветовые настройки сохраняются; устаревший результат не заменяет новые правки.

Для остальных фото откройте «Редактировать фото» → «Улучшить качество». Сначала сохраните изменения обрезки и цвета. Можно закрыть окно во время обработки. Сохранение без изменения настроек оставляет улучшенную версию, а новые правки вычисляются из оригинала; фон при необходимости улучшится повторно.

После обработки улучшенное фото появляется на месте оригинала. Кнопка «Открыть оригинал» возвращает исходное фото с настройками обрезки и цвета; «Открыть улучшенное» показывает результат без повторной обработки. «Отменить улучшение» возвращает фото до апскейла, сохраняя прежние обрезку и цвет. Автоматическая очередь уважает этот откат; повторное улучшение запускается вручную.

Ручное улучшение — ×2, автоматическое — до Full HD, с сохранением пропорций. Пределы: ×4 и 4096 px по длинной стороне, исходник до 8 Мп/15 МБ; очень маленькие и панорамные снимки могут остаться ниже Full HD. Фото от 4096 px не уменьшаются. Детали сервиса и проверок — `services/upscale/README.md`. Вне Compose автоматическая обработка отключена; `UPSCALE_ENABLED=true` предназначен для веб-контейнера в этой сети.
